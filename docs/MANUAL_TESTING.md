# Ручна перевірка Portico

Цей документ задає сценарії перевірки; наведені нижче рядки **не означають, що справжній Wine або ігри вже запускалися**. На момент підготовки документа інтеграційні перевірки з Windows Steam, Heroes of Might and Magic III, Jagged Alliance 2, Divinity та Gothic ще не виконано. Перевірки Wine й результат `swift test` фіксуються окремо та підтверджують лише фактично виконані сценарії.

## Підготовка

Використовувати тестовий обліковий запис macOS або окрему машину з порожніми даними Portico. Не видаляти наявну користувацьку бібліотеку заради тесту. Підготувати власну інсталяцію Wine, невеликий довірений Windows `.exe`, інсталятор `.exe`, інсталятор `.msi` та одну гру. Для 3D-тестів потрібна справжня гра, а не `notepad.exe`.

Основний runtime-тест виконується із самостійним Wine, що дотримується `WINEPREFIX`. Внутрішні wrappers CrossOver/GPTK та їхні графічні бібліотеки не слід вважати сумісними автоматично: для них потрібна окрема перевірка контракту запуску. Не використовувати наявні користувацькі bottles CrossOver як тестові.

У протоколі записати дату, commit або версію Portico, модель Mac, обсяг пам'яті, macOS, архітектуру й `--version` рушія, графічний backend, магазин і версію гри. Якщо компонента немає, позначати залежний тест як «не виконано», а не «пройдено».

## Базові сценарії

| Сценарій | Дії | Очікуваний результат |
|---|---|---|
| Чистий запуск | Зібрати `./scripts/build-app.sh --without-runtime` або підготувати runtime для повної збірки; відкрити `dist/Portico.app` у чистому обліковому записі. | Порожня бібліотека, немає вигаданих встановлених ігор, застосунок пояснює першу дію. Навігація розділами, включно зі Steam, працює. |
| Рушій відсутній | Запустити без Wine; відкрити «Рушій». | Можна вибрати шлях або відкрити підготовку компонентів. Windows-запуск і створення готового середовища не позначаються доступними до перевірки Wine. Без дії користувача завантаження не починаються; Gatekeeper не змінюється. |
| Хибний шлях | Ввести відсутній файл, каталог, потім звичайний невиконуваний файл; перевірити кожен. | Зрозуміла помилка; файл налаштувань не отримує підтверджений неробочий runtime. Повторний вибір залишається доступним. |
| Справжній рушій | Вибрати наявний `wine` і виконати перевірку. | Показано версію, успішний шлях зберігається. Це перевірка Wine, а не сертифікат сумісності ігор. |
| Wrapper CrossOver | На тестовій машині вибрати внутрішній runtime із `CrossOver.app` і спробувати створити середовище. | До ініціалізації Windows-префікса з'являється помилка непідтримуваного wrapper. Наявні bottles CrossOver не змінюються. |
| Перезапуск | Закрити застосунок і відкрити знову. | Бібліотека та шлях зберігаються; перед створенням нового середовища рушій можна перевірити повторно. |
| Створення середовища | Створити середовище з пробілами й кирилицею в назві. | Стан підготовки змінюється готовністю лише після завершення ініціалізації; у `Bottles/<UUID>` з'явилися `drive_c` і реєстр. UI не зависає. |
| Помилка підготовки | На окремій тестовій інсталяції вибрати рушій, який проходить `--version`, але не може ініціалізувати префікс. | Середовище отримує стан помилки, доступні журнал і повторна спроба. Готовність не показується. |
| Збій застосунку під час підготовки | На тестовій машині перервати Portico під час створення й відкрити знову. | Перерване середовище не залишається назавжди в стані створення й не позначається готовим; після помилки можна повторити спробу. |
| Wine Configuration | Відкрити налаштування готового середовища, змінити допустиме налаштування й закрити вікно. | Відкривається `winecfg` потрібного префікса; після закриття середовище знову доступне для операцій. |
| Інсталятор EXE | Запустити довірений `.exe`-інсталятор, пройти встановлення в `C:`. | Файли з'являються в потрібному `drive_c`; журнал містить запуск і завершення. Завершення інсталятора не є доказом успішного встановлення гри. |
| Інсталятор MSI | Повторити з `.msi`, зокрема зі шляхом із пробілами. | Використовується Windows Installer через Wine; аргументи та шлях зберігають межі, відкривається потрібний пакет. |
| Додавання гри | Вибрати встановлений `.exe`, назву, середовище, аргументи запуску й робочу папку. | З'являється картка з вибраним середовищем; після перезапуску дані збережено. Відсутній файл і файл іншого формату відхиляються. |
| Параметри гри | Додати дві гри в різні середовища. Для однієї змінити назву, `.exe`, аргументи й робочу папку, потім вибрати інше готове середовище. Перезапустити Portico. | Зміни збережено лише для вибраної гри; її ідентифікатор, обране й історія запусків збережені. Зміна середовища не переносить файли гри та збереження. |
| Робоча папка | Запустити діагностичний `.exe` з порожнім полем, потім із явним каталогом із пробілами. Перевірити відсутній каталог і звичайний файл замість папки. | Типово процес отримує каталог `.exe`, за явного вибору — зазначений каталог. Некоректна папка відхиляється зі зрозумілою помилкою. |
| Аргументи | Кнопкою «Додати аргумент» створити кілька полів, включно зі значенням із пробілами та порожнім значенням. Видалити одне поле кнопкою мінус, зберегти й знову відкрити налаштування; перевірити діагностичний `.exe`. | Гра отримує решту аргументів окремими значеннями й у тому самому порядку, включно з порожнім аргументом; назва файлу не інтерпретується оболонкою. |
| Налаштування Steam-картки | Відкрити налаштування імпортованої Steam-гри й перейменувати її. | Змінюється лише назва; App ID та шлях клієнта зберігаються. Параметри `.exe`, робочої папки й аргументів не пропонуються: їх налаштовують у Steam. |
| Справжній запуск | Запустити `.exe`, відкрити вікно застосунку, потім закрити його штатно. | Стан запуску відповідає сесії, UI доступний. Після штатного завершення запуск знову доступний. |
| Конкурентні дії | Під час роботи однієї гри спробувати запустити іншу в тому самому середовищі, інсталятор і `winecfg`. | У цьому середовищі не починається конкурентна керована операція. Інше середовище залишається незалежним. |
| Зупинення | Запустити процеси у двох різних тестових середовищах і зупинити лише перше. | Завершуються процеси вибраного префікса; друге середовище продовжує працювати. У першому знову доступний запуск. |
| Відсутній EXE | Закрити гру, тимчасово перейменувати тестовий `.exe`, запустити картку. | Зрозуміла помилка; інтерфейс не залишається в стані запуску. Повернути файл після перевірки. |
| Журнал | Відкрити журнал після помилки й після успішного запуску, натиснути оновлення, експортувати. | Видно діагностичні дані вибраного середовища; збережений файл читається. Переконатися, що експортований текст — відображена частина журналу, а не обіцянка повної траси. |
| Бібліотека | Додати дві картки, перевірити пошук, обране й нещодавні після завершеного запуску. | Фільтри показують очікувані записи; обране зберігається після перезапуску. |
| Видалення картки | Видалити картку, яка не працює. | Запис зникає, встановлений `.exe` та збереження залишаються на диску. |

## Windows Steam

Для цього сценарію потрібен готовий самостійний Wine. Використовувати нове тестове середовище й власний обліковий запис Steam із невеликою доступною Windows-грою. Пароль і Steam Guard вводить користувач у вікні клієнта. Купувати гру для перевірки не потрібно. Окремо зафіксувати версію клієнта Steam. Якщо робочого Wine немає, весь сценарій позначається як «не виконано».

| Сценарій | Дії | Очікуваний результат |
|---|---|---|
| Немає середовища | Відкрити розділ «Steam» із порожньою бібліотекою або лише неготовими середовищами. | Показано шлях підготовки Wine й створення середовища. Встановлення Steam не починається без готового середовища. |
| Встановлення клієнта | Вибрати готове середовище й встановити Steam. Пройти майстер, залишивши стандартний каталог на `C:`. | Завантажується офіційний Windows `SteamSetup.exe`; він запускається через Wine вибраного префікса. Поява `steam.exe` перевіряється окремо від завершення інсталятора. |
| Помилка завантаження | На тестовому підключенні перервати завантаження інсталятора, потім повторити. | Помилку видно, кнопки знову доступні; неповний файл не запускається як інсталятор. |
| Вхід та оновлення | Відкрити Steam, завершити оновлення клієнта й увійти вручну. | Працює вікно Windows-клієнта; Portico не запитує пароль і Steam Guard. |
| Розділи Steam | Із Portico відкрити бібліотеку, магазин і завантаження, зокрема коли Steam уже працює. | Вибраний розділ відкривається у Windows-клієнті того самого середовища. Steam для macOS не відкривається. Нова конфліктна Wine-сесія не створюється. |
| Встановлення гри | У Steam встановити невелику доступну Windows-гру; до завершення оновити список Portico. | Прогрес завантаження показує Steam. Незавершена інсталяція не з'являється як готова для імпорту гра. |
| Імпорт | Після завершення встановлення оновити список та імпортувати гру. Повторити імпорт. | Створюється одна картка з правильними назвою, App ID та середовищем; повторний імпорт не створює дублікат. |
| Запуск картки | Запустити імпортовану гру із закритим, потім із уже відкритим Steam. | Команда запуску за App ID передається Windows-клієнту в тому самому префіксі. Якщо Steam запитує компоненти першого запуску, користувач завершує їх встановлення в клієнті. Успішне передавання команди не вважається підтвердженим запуском 3D. |
| Два середовища | Створити два тестові середовища зі Steam; перемкнути вибране в Portico, оновити список і відкрити бібліотеку. | Клієнт, список встановлених ігор та імпорт прив'язані до вибраного середовища; однаковий App ID допустимий у різних середовищах. |
| Зупинення | З активними Steam і грою зупинити вибране середовище; залишити друге тестове середовище активним. | Steam і гра вибраного префікса завершуються; друге середовище продовжує працювати. |
| Відсутній клієнт | Закрити Steam, тимчасово перейменувати `steam.exe` у тестовому префіксі, запустити картку. | Зрозуміла помилка про відсутній Windows-клієнт; немає перенаправлення в Steam для macOS. Відновити файл. |
| Перезапуск Portico | Закрити Wine, перезапустити Portico й відкрити імпортовану картку. | App ID та прив'язка до середовища збережені; запуск знову відбувається через Windows Steam. |

## Видалення ігор (лише на окремих тестових даних)

- Натиснути кнопку Кошика на картці звичайної гри й закрити вікно кнопкою «Скасувати»: картка, файли та `library.json` не змінюються. Повторити через контекстне меню.
- Вибрати «Лише з бібліотеки» й підтвердити: зникає тільки вибрана картка, лічильник оновлюється, після перезапуску видалення зберігається. Файли гри, збереження та інші картки залишаються.
- Для одноразової `.exe`-гри вибрати «Видалити з диска», вибрати її папку, перевірити показаний шлях і підтвердити переміщення в Кошик. Папка зникає з початкового місця, у Кошику є її файли, картка зникає після успішної операції. Сусідня гра та збереження поза папкою залишаються. Скасування вибору папки нічого не видаляє.
- Спробувати вибрати спільну папку Games, корінь середовища, Windows, символьне посилання, папку без вибраного `.exe` і папку з другою карткою: дія блокується з поясненням. Перевірити блокування видалення під час запуску й підготовки.
- Для одноразової Steam-гри перевірити, що підтвердження відкривається саме у Windows Steam вибраного середовища. Скасувати у Steam: файли та картка залишаються. Повторити й завершити видалення, тримаючи вікно Portico відкритим: після зникнення папки й оновлення списку зникає картка. Закрити Steam без видалення: можна повторити дію.
- Для CrossOver перевірити пояснення з назвою середовища та відкриття CrossOver. Вилучення лише картки не змінює ярлик або середовище CrossOver.
- Повторити основні вікна мовами ENG і UKR; довгі назви й шляхи мають переноситися без обрізання кнопок.

## Сховище

На копії тестових даних перевірити відмову читання пошкодженого `library.json` і файлу з непідтримуваною версією схеми. Застосунок має показати помилку й зберегти початкові байти файлу. Відкрити копію бібліотеки, збереженої до підтримки Steam: записи без `steamAppID` мають завантажитися й продовжити звичайний запуск `.exe`. Пошкоджений Steam App ID у тестових даних має відхилятися без перезаписування файлу. Перевірити шляхи середовищ із UUID: довільна назва середовища не має створювати каталогів поза `Bottles`.

Заборона запису в тестовий каталог має спричиняти помилку збереження, а не повідомлення про успішне додавання гри. Перед кожною такою перевіркою закривати Portico й зберігати резервну копію тестових даних; після перевірки відновлювати права та вміст.

## Цільові ігри

Список нижче задає початкові приклади для загальної бібліотеки. Нові ігри додаються тим самим способом; кожна версія та середовище мають власний протокол перевірки.

**Heroes of Might and Magic III, оригінал / Complete, Windows.** Записати магазин, видання, мову, build і модифікації. Встановити власну копію в окреме середовище, додати ігровий `.exe` та перевірити робочу папку. Запустити сценарій або кампанію, перевірити карту пригод, екран міста, рух героя й бій протягом щонайменше 15 хвилин. Перевірити звук, мишу й клавіатуру, доступні віконний і повноекранний режими. Зберегти гру, повністю завершити сеанс, повторно запустити з Portico й завантажити збереження. HD Edition, HD Mod і HotA перевіряти окремо; зазначити вибраний `.exe` або лаунчер і версію модифікації. Зберегти журнал та спостережувані помилки. [Complete на GOG](https://www.gog.com/en/game/heroes_of_might_and_magic_3_complete_edition), [HD Edition у Steam](https://store.steampowered.com/app/297000/).

**Jagged Alliance 2, оригінал / Gold, Windows.** Записати магазин, видання, мову, build і наявність модифікацій. В окреме середовище встановити основну гру, додати її `.exe`, залишити робочу папку порожньою для запуску з каталогу `.exe` або зазначити фактичний каталог даних. Перевірити головне меню, створення нової гри, стратегічну карту, вхід у сектор і щонайменше 15 хвилин гри з тактичним боєм. Перевірити мишу й клавіатуру, звук і мовлення, збереження, повний вихід і завантаження збереження після повторного запуску з Portico. Зберегти журнал та опис збоїв зображення або введення. **Unfinished Business і мод 1.13 перевіряти окремо**, з окремими картками та середовищами; не зараховувати їм успіх основної гри. ## Перемикання ENG / UKR

- У верхній панелі перемкнути UKR → ENG → UKR на сторінках бібліотеки, Steam, середовищ, рушія та журналу. Заголовки, кнопки, підказки, порожні стани й статуси мають оновлюватися одразу.
- Перевірити перемикач у вікні першого запуску: заголовки, етапи завантаження й повідомлення Portico змінюють мову без закриття вікна.
- Вибрати «Обране» або «Нещодавні», ввести пошук і перемкнути мову. Фільтр, запит і вибрана сторінка зберігаються; назви ігор та середовищ не перекладаються.
- Кожною мовою відкрити форми створення середовища й налаштувань гри, меню застосунку та діалоги вибору файлів. Перевірити локалізовані заголовки Portico й відсутність обрізаних підписів. Системні кнопки macOS і зовнішній інтерфейс Wine/Steam використовують власні мовні налаштування.
- Під час безпечної тестової операції перемкнути мову: поточний стан середовища й Steam має оновитися; операція продовжує виконуватися.
- Вибрати ENG, штатно завершити Portico й відкрити знову: мова залишається ENG. Повторити для UKR. Попереднє застаріле значення мови автоматично замінюється на UKR; перемикач пропонує лише ENG і UKR. Вибір зберігається в UserDefaults (`Portico.interfaceLanguage`) окремо від бібліотеки.
- В англійському інтерфейсі перевірити дату створення середовища й помилку валідації. Користувацькі шляхи, назви та початковий результат сторонніх процесів залишаються без змін.

Ці пункти — сценарії ручної перевірки. Автотести `LocalizationTests` окремо перевіряють збереження вибору, інтерполяцію та відповідність плейсхолдерів перекладів.

## Gallery and appearance

- Switch the sun/moon control in the header between Light and Dark. Check the library, Steam, environments, engine, logs, setup, settings and open dialogs; quit and reopen to confirm the theme persists.
- Switch UKR/ENG in the header and in Settings. Both controls should update immediately without losing the current theme or game selection.
- Select a game tile and verify that Edit, Options, Favorite and Play refer to that game. Options opens launch parameters expanded for direct executable games.
- Search, switch Favorites/Recent, and remove a favorite while Favorites is active. Selection must follow the visible results; no launch bar should remain when no games match.
- Open the ellipsis menu and the existing removal dialog, then cancel. Imported CrossOver games retain their own launch route, favorite, Finder and removal actions.
- Check a long game name, multiple rows, an empty library and a narrow window. All games use the same built-in placeholder; no cover images are downloaded.
- Use the isolated UI smoke fixture for launch/stop checks. Simulator UI evidence does not establish actual Windows game compatibility.

## Reviewed support reports

- Open Report from the header. Confirm that app/macOS versions, architecture, selected game and redacted environment log are visible before sending. Cancel must close without uploading.
- Reproduce a synthetic launch error with the isolated Wine simulator. The error offers Report and Cancel; Report pre-fills the error and diagnostics, while Cancel returns to the library.
- Open Help > Report while editing a game, then cancel the report. Unsaved editor fields must remain intact.
- Review and consent before Send. Editing the text clears consent. An unchanged retry reuses its report ID; editing a previously attempted payload creates a new ID.
- A successful receipt must match the submitted report ID. Network errors preserve the draft. Use synthetic data for live API verification, never real user diagnostics during QA.
